## Central content (central/) — fetched by every repo's loader at session start
- `MANIFEST.txt`: first line `version: X.Y.Z` (the only place the version lives), then every file the loader fetches; rebuilt with `tools/build_manifest.py`
- Rules text `rules/CLAUDE-rules.md`, injected at session start
- All text read from subprocesses and hook input is UTF-8 whatever the PC language (3.1.15: gbk fix)
- End-of-task summary (`stats.py`, Stop, systemMessage — no AI turn): tokens and time by model incl. helpers, with the re-read part shown, main vs helpers share (v3.1.26), tokens by activity — planning / coding / testing / git & pull requests / talking / other, an estimate per step classified on all its records: test commands and screenshot/capture scripts > edits or worker hand-overs > reading, searching, read-only shell commands, plan mode, Explore/Plan helpers > git/gh > text only (v3.1.25/26); helper files counted once even when both search paths name the same folder (v3.1.26) — hand-overs, in-between messages (texts before the last of each request, v3.1.25), refusals, send-backs; fresh-session hint for long sessions; logs what it showed or why not to `.claude/state/stats.jsonl`
- Version line `Rules vX · branch · setup <state>` shown in the Stop notice (stats.py) after the session's first reply and atop every summary (v3.1.23: the desktop app does not show session-start notices); replies never write it
- Hand-off and plan versions (v3.1.24): `handoff-guard.py` (Stop) sends back a Plan vN no plan file in `plans/` has yet, a ledger plan name carrying an older version, and a restart line with the wrong plan name or branch, an unpushed record or missing not-complete rows; `plan-gate.py` gives the hand-off with the exact restart line after a merge or once a session passes `fresh_session_hint_tokens` (once per session, from `stats.py`'s token store), and turns a restart line into a switch-branch-and-read-first instruction; Completion lines list blocked, queued and waiting items, and SUPERSEDED rows are not counted; a send-back carries only the version line; Where we are points to the plan file, commits and pull requests by path or number (idea borrowed from mattpocock/skills `handoff`); the validation line is written once (rule only, no check); Build and Check counted apart — `Completion: Build n of m done (p%) · Check c of d` (Check = row labelled `(Check)` or waiting on the user; an unlabelled waiting row is sent back to get the label), checks never send back, hand-off with the first check as next when Build reaches 100% (completion-guard sends back a Build-100% report until the restart line stands in the reply or in Where we are), a problem found in checking becomes a new Build row; validation-line sends back colour codes and sizes (#hex, px/pt/rem/em) in the three closing lines; a change from what the user approved is a ❓ Decision, never news (rule + session-start fact); plan-guard sends back stages not marked Build or Check, and reads plan files from the repository's plans/ when the call carries no plan text
- `setup-guard` (Stop): no other answer before the setup-update branch exists
- Completion counted by plan (`<plan name> · Stage k of M` rows) with QUEUED and WAITING ON YOU states
- Plan check: framed Summary table, changes box whenever Rev labels exist, stage-count line; Fable-to-Opus tip after a Fable plan passes
- Skill router v2: hz-reviewer, hz-planner, hz-chat-handoff, hz-designer (account skills, synced into Claude Code as anthropic-skills:<name>), hz-change-guard (central copy)
- QA/QC: rules section for everything handed to the user; qc-guard (Stop) sends back destructive instructions without the separate-yes form; packages are always full
- Switchboard `hooks/dispatch.py`: the stub registers it for UserPromptSubmit, PreToolUse and Stop (PostToolUse and SubagentStop removed in v3.1.16: no checks used them) (PreToolUse matcher Edit|Write|MultiEdit|NotebookEdit|Bash|Agent|Task|WebFetch|mcp__.*); `config.json` → `dispatch` lists the checks per event/tool; Stop/SubagentStop run every check and send all block reasons back in one message, keeping the notices (summary, version line) beside a send-back and logging every Stop to `.claude/state/dispatch.jsonl`; other events: first block/deny wins; contexts are joined
